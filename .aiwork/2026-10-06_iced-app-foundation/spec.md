# Spec — Photo Cruiser (iced), foundation

A fast photo browser/editor in Rust. All photo logic lives in a GUI-free library. The same
functionality is reachable from three front ends: the iced GUI, a CLI, and agents (through the CLI and
a scriptable GUI mode). This spec covers the foundation (milestone 1) and fixes the architecture
for later milestones.

## Goals

- **Parity with the prototypes:** browse a folder with ←/→ in natural filename order, AVIF/HEIC/JPEG/PNG/GIF/WebP/BMP, and a free-ratio crop with 50% dim.
- **Hard split:** `core` has no GUI dependencies; the GUI is a thin shell over `core`.
- **CLI first-class:** everything `core` can do is scriptable and has JSON output.
- **Agent-operable:** an agent can build, test, and drive both the CLI and the GUI and get evidence (JSON state + PNG) without OS input injection or desktop screenshots.
- **Ready for fast editing:** the data model is a non-destructive edit stack, with a CPU reference implementation now and a GPU preview later.

## Non-goals (for now)

HEIC output, a catalog database, multi-folder libraries, a native SMB client, a live COSMIC theme reload, and packaging. Later milestones cover them.

## Workspace layout

```
photo-cruiser/
  Cargo.toml              # [workspace], shared deps, edition 2024
  justfile                # check, test, run, shot, cli shortcuts
  crates/
    core/                 # lib  photo_cruiser_core — no GUI, no async runtime
    cli/                  # bin  pcr
    app/                  # bin  photo-cruiser (iced 0.14)
    gpu/                  # (milestone 3) wgpu preview pipeline, parity-tested against core
  fixtures/               # small synthetic images, generated by a script, committed
  .aiwork/
```

The dependency direction is `cli → core` and `app → core (+ gpu later)`. Nothing depends on `app` or `cli`.

## `core` crate

| Module | Responsibility |
| --- | --- |
| `source` | `Source` trait: list entries and open bytes. Milestone 1 implements `LocalDir` (GVfs-mounted SMB paths work through it unchanged). A native SMB source can come later behind the same trait. |
| `catalog` | `Folder { path, entries: Vec<Entry> }`. Filtering: top level only, hidden files skipped, case-insensitive extensions `jpg jpeg png gif webp bmp avif heic heif`. Natural, case-insensitive sort. |
| `decode` | `decode(path) -> Result<Decoded>`. `image` handles the classic formats (with EXIF orientation applied); `libheif-rs` (`v1_17`) handles AVIF/HEIC/HEIF. Optional `max_side` downscaling for previews. `Decoded` keeps the source dimensions separately. |
| `geom` | `Rect` in source pixels, contain-fit math (`fit_rect`), mapping between view and source coordinates, clamping. |
| `edit` | `EditStack { ops: Vec<Op> }`, serde, versioned. Milestone 1 has only `Op::Crop(Rect)`. Later ops: Exposure, Contrast, LocalContrast, Sharpen, etc. |
| `render` | CPU reference pipeline: `render(&Decoded, &EditStack, RenderOpts) -> RgbaImage`. Works in f32 linear internally once tonal ops arrive. This implementation defines correctness. |
| `export` | Encodes JPEG, PNG and (later) WebP/AVIF. |
| `error` | A single `Error` enum (thiserror). No panics on bad input files. |

Rules:
- `core` is synchronous and pure where possible. Concurrency (decode thread, stale-request dropping) belongs to the callers, which get a small helper: `Loader`, which keeps one job in flight and always serves the latest request.
- Every public operation can be driven by the CLI and covered by tests.

## `cli` crate (`pcr`)

```
pcr list <dir> [--json]                    # sorted entries, index, dims if --probe
pcr info <file> [--json]                   # format, dims, orientation, decode ms
pcr render <file> [--edits e.json] [--crop x,y,w,h] [--max-side N] -o out.png
pcr export <file> --edits e.json -o out.jpg [--quality 90]
pcr app <dir> [--script s.json] [--shot out.png] [--dump-state]   # launches the GUI (see below)
```

- `--json` gives stable, documented output. Exit codes: 0 ok, 1 usage, 2 I/O, 3 decode.
- Uses `clap` (derive). Integration tests with `assert_cmd` against `fixtures/`.

## `app` crate (iced 0.14)

- iced features: `default-features = false`, plus `wgpu, tiny-skia, crisp, web-colors, thread-pool, x11, wayland, canvas, image-without-codecs`. **`web-colors` is required** for correct 50% dimming.
- Structure, ported from the prototype:
  - `state.rs`: folder, index, loader, crop, mode
  - `message.rs`
  - `view.rs`
  - `crop_overlay.rs`: the canvas, which also owns keyboard handling
  - `theme.rs`: COSMIC RON → `Theme::custom`, with a dark fallback
- **Actions:** a serde `Action` enum is the single entry point for behaviour: `Open(path)`, `Next`, `Prev`, `Goto(i)`, `ToggleCrop`, `SetCrop(Rect)`, `ClearCrop`, `Quit`. Keyboard, buttons, scripts, tests and a future control socket all produce `Action`s. `Message` wraps them, plus internal events (decode done, etc.).
- **Keyboard** goes through a focused widget (the canvas overlay), not `event::listen` subscriptions, because `iced_test` doesn't feed subscriptions.
- **Loading:** one decode in flight for the latest index, ±1 preload when idle, a generation counter per folder, and display downscaling to `max_texture_side`.
- **Window:** set an application id (`com.lukastrumm.PhotoCruiser`, placeholder). Title: `Photo Cruiser — <folder>`. Status line: `name — i / N[ — crop W×H @ X,Y]`.

### Agent and script mode

- `photo-cruiser <dir> --script steps.json --shot out.png --dump-state state.json`:
  1. open the real window;
  2. apply the `Action`s from the script in order, waiting until loading is idle between steps;
  3. capture `window::screenshot` to `--shot`;
  4. write the app state (index, file, crop, mode, title, status, errors) as JSON;
  5. exit 0, or non-zero on any error.
- This is the supported way for agents to check the real window. It needs no desktop screenshot and no input injection.
- A JSON-RPC control socket (`pcr ctl next`, `pcr ctl shot`) is **deferred** until there's a need. The `Action` enum makes it cheap to add.

## Testing

| Layer | Tool | What |
| --- | --- | --- |
| core | `cargo test` | natural sort, filtering, `fit_rect`/mapping, crop clamping, decoding every fixture format, edit-stack serde round trip, golden images for `render` (tolerance-based) |
| cli | `assert_cmd` | each subcommand against fixtures, the JSON schema, exit codes |
| app | `iced_test` | Emulator: click by text, mouse drags through real widgets, `Simulator::snapshot` (with a delay for async uploads); keys via the canvas widget |
| app (real window) | script mode | `just shot`: runs the script, then checks the state JSON and the PNG |

- **Fixtures:** small synthetic images (gradients, a checkerboard, EXIF-rotated JPEG, AVIF, HEIC, uppercase extensions, a broken file), generated by `just fixtures` and committed. HEIC fixtures come from `pillow-heif` via `uv run`. **The personal photos are never committed.** Large local sets are opt-in via the `PC_PHOTOS` env var (e.g. `~/sandbox/photo-cruiser/test-photos`).
- **CI (later):** Linux first; add Windows and macOS when packaging starts.

## Tooling

- Every build sets `PKG_CONFIG=/usr/bin/pkg-config` (exported in the justfile).
- `just check` = fmt + clippy (`-D warnings`) + test. `just run [dir]`, `just shot [dir]`, `just cli …`.
- Agent rules, also to go into the project's CLAUDE.md: no `wtype`/OS input injection, no full-desktop screenshots, use `trash-put` instead of `rm`, and close every window that gets launched.

## Milestones

1. **Foundation (this spec):** workspace; `core` (catalog, decode, geom, edit with Crop, render, export PNG/JPEG); CLI `list/info/render/export`; GUI parity with the prototype on the `Action` architecture; script mode; tests at every layer.
2. **Edit stack:** Exposure, Contrast, Sharpen (unsharp mask) in core as f32 linear ops, a side panel with sliders, sidecar files (`<photo>.pcedit.json`), and an "apply crop on export" step.
3. **GPU preview:** `gpu` crate (wgpu compute/shaders) mirroring the core ops and feeding a shader widget. A parity test against the CPU reference. Target: under 16 ms per slider update at screen resolution.
4. **Local contrast:** a local-Laplacian (or guided-filter) implementation, CPU first, then GPU.
5. **Conversion:** batch `pcr export` (JPEG/PNG/WebP/AVIF) and a GUI export dialog.
6. **Sources and polish:** an SMB/network source (GVfs first), thumbnails and cache, live COSMIC theme reload, a desktop entry.
7. **Distribution:** cargo-dist; bundle libheif on Windows/macOS; an AppImage or Flatpak; CI on 3 OSes.

## Acceptance (milestone 1)

- `pcr list ~/sandbox/photo-cruiser/test-formats --json` lists 7 entries in natural order.
- `pcr render <heic> --crop 100,100,400,300 -o out.png` writes a 400×300 PNG.
- `photo-cruiser <dir> --script <next×6, toggle crop, set crop> --shot s.png --dump-state st.json` exits 0. The state shows index 7/7 and the crop, and the PNG shows the dimmed overlay.
- `just check` is green. The `iced_test` suite covers browsing all fixture formats, clamping, crop draw/move/resize and Esc.

## Open questions

- Licence of the project itself. MIT/Apache would match iced; libheif is LGPL and linked dynamically.
- Processing core: own Rust f32 pipeline (default), or libvips bindings for some ops (LGPL, adds a C dependency)?
- Sidecar format and location: next to the photo, or in a central store for read-only and SMB sources?
- Whether to adopt libcosmic on Linux for the full COSMIC look. The shell is thin enough that this stays an option.
