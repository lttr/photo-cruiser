# pcr: Photo Cruiser from the command line

Generated by `pcr skill` (pcr {{version}}). Regenerate it after updating pcr.

`pcr` reads and writes the same files as the Photo Cruiser app. Edits are non-destructive: every photo
keeps its untouched original in a backup, so any save can be reverted.

## Rules

- Pass `--json` to every command except `app` and parse stdout. Field names are stable. Errors go to
  stderr; with `--json`, stdout also gets `{"error": {"kind": ..., "message": ...}}`.
- Exit codes: 0 ok, 1 usage, 2 I/O, 3 decode or invalid input. The error kinds are listed below.
- Change photos only through `pcr save` and `pcr revert`. Never write, move or delete anything in
  `.photo-cruiser/` yourself, and never overwrite a photo with another tool: the backups and sidecars
  have to stay consistent.
- Preview before saving many photos: `pcr render ... --max-side 800 -o /tmp/...` writes a small PNG or
  JPEG and changes nothing. Look at a few previews, or check numbers, before you run `save` on a batch.
- Edit stack files and previews are scratch files. Put them in a temp folder, not next to the photos
  (`list` skips hidden files and non-photo extensions only).
- Saving changes the user's photo files. For a large batch, say what you will do and how to undo it
  (`pcr revert`) before you start, unless the user already asked for exactly that.

## Files on disk

```text
<dir>/IMG_1234.jpg                              the photo; after a save, the edited result
<dir>/.photo-cruiser/edits/IMG_1234.jpg.json    sidecar with the edits, keyed by the original's name
<dir>/.photo-cruiser/originals/IMG_1234.jpg     the untouched original, moved there by the first save
```

- A photo without a sidecar has no edits. The first save moves the original into `originals/` and writes
  the rendered result under the photo's name. Later saves render from that original again, so quality
  never degrades and edits never stack up: each save replaces the previous result.
- `pcr revert` moves the original back, byte for byte, and deletes the sidecar.
- Saving keeps the format for JPEG (original quantisation tables, raised to at least quality 95), PNG
  and WebP. AVIF, HEIC, BMP and GIF photos become JPEG: `IMG.HEIC` turns into `IMG.jpg`, the `path` in
  the save report is the new name, and the sidecar and backup keep the original name. Save refuses
  animated images (`animated`), 16-bit PNGs (`high_bit_depth`), a converted name that another file
  already has (`name_taken`) and read-only folders (`read_only`).
- EXIF and ICC profiles are kept; EXIF sizes are updated.
- In a read-only folder the sidecar goes to `$XDG_DATA_HOME/photo-cruiser/edits/<sha256 of the photo
  path>.json` instead. Edits still work there, but save does not.

### Sidecar JSON

```json
{
  "version": 1,
  "ops": [{"op": "crop", "x": 10.0, "y": 10.0, "w": 100.0, "h": 80.0}],
  "saved": {"ops": [{"op": "crop", "x": 10.0, "y": 10.0, "w": 100.0, "h": 80.0}]},
  "file": {"name": "IMG_1234.jpg", "size": 1598, "mtime": "2026-10-18T19:15:58.324333397Z"}
}
```

- `version`, `ops`: the current edit stack (format below), which is what the app shows.
- `saved.ops`: the stack the photo file was rendered from. It is absent if the photo was never saved.
  The photo is *dirty* when `ops` differs from `saved.ops`. The app saves dirty photos by itself;
  `pcr save FILE` (without `--edits`) saves them too.
- `file`: name, size and mtime (RFC 3339, UTC) of the photo as the last save left it. If the photo
  changed since then (another program edited it), the edits are *stale*: pcr prints a warning, drops the
  sidecar and treats the current file as the original.

Read sidecars with `pcr edits FILE --json`, which also reports `dirty` and the `backup` path. Don't
parse them directly.

## Edit stack JSON

This is what `--edits FILE` takes, and the `ops` that `render`, `edits` and the sidecar print:

```json
{"version": 1, "ops": [
  {"op": "crop", "x": 120, "y": 0, "w": 3000, "h": 2000},
  {"op": "rotate", "quarters": 1},
  {"op": "adjust", "tool": "levels", "value": 1},
  {"op": "adjust", "tool": "exposure", "value": 0.3}
]}
```

- `version` must be 1. A missing `ops` means no edits. An empty stack means "the original".
- `crop`: a rectangle in pixels of the **original** at full resolution, after EXIF orientation (the
  `width` × `height` that `pcr info` reports for the original). It is clamped to the image; a crop with
  nothing left after that is the error `empty_crop`. At most one per stack.
- `rotate`: clockwise turns of `quarters` × 90° (1–3). At most one per stack. Put it after the crop
  (as pcr and the app do), so the crop rectangle is in unrotated coordinates of the original.
- `adjust`: a one-slider tool at `value` (tools below). At most one per tool. Values outside the range
  are clamped, and the neutral value does nothing (leave the op out instead). Adjustments run after the
  geometry, in the order of the table below, wherever they are in `ops`.
- The geometry ops run in stack order, then the adjustments, then (`render` only) the `--max-side`
  downscale.

### Tools

{{tools}}

"Opens at" is the value the app starts the slider at, and the value `render --adjust TOOL` uses when
you give no value. "auto" means pcr measures it on the cropped photo. `render --json` prints the value
it used in `ops`, so you can reuse it in a stack file.

## The original's size after a save

After a save, the photo file holds the edited result: `pcr info PHOTO` reports the *cropped* size. Crop
coordinates always refer to the original, so get its size from the backup:

```bash
b=$(pcr edits "$f" --json | jq -r '.backup // empty')
pcr info "${b:-$f}" --json | jq '{width, height}'
```

## Workflows

Inspect a folder (`index` is the 0-based display order, the same as the app's):

```bash
pcr list ~/Photos/trip --probe --json | jq -r '.entries[] | select(.error == null) | .path'
```

Edit one photo: preview, then save. `save --edits` replaces the photo's whole stack:

```bash
pcr render IMG.jpg --no-edits --crop 0,250,4000,2250 --adjust levels --adjust exposure \
  --max-side 1200 -o /tmp/pcr/IMG.png --json      # look at it; .ops holds the auto values
pcr render IMG.jpg --no-edits --crop 0,250,4000,2250 --adjust levels --adjust exposure \
  --max-side 64 -o /tmp/pcr/x.png --json | jq '{version: 1, ops}' > /tmp/pcr/IMG.edits.json
pcr save IMG.jpg --edits /tmp/pcr/IMG.edits.json --json
```

`--crop` is added after the photo's own edits. If the photo is already cropped, pass `--no-edits` (or
`--edits`); otherwise the second crop applies to the cropped image.

Add a change to the existing edits (keep the crop, set exposure):

```bash
pcr edits "$f" --json | jq '{version: 1, ops: ([.ops[] | select(.tool != "exposure")]
  + [{op: "adjust", tool: "exposure", value: 0.5}])}' > /tmp/pcr/e.json
pcr save "$f" --edits /tmp/pcr/e.json --json
```

Apply the same thing to many photos. Run them one at a time, collect the failures and keep going:

```bash
mkdir -p /tmp/pcr
pcr list ~/Photos/trip --json | jq -r '.entries[].path' | while IFS= read -r f; do
  n=$(basename "$f")
  if r=$(pcr render "$f" --no-edits --adjust levels --max-side 64 -o "/tmp/pcr/$n.png" --json) \
    && jq '{version: 1, ops}' <<<"$r" > "/tmp/pcr/$n.json" \
    && pcr save "$f" --edits "/tmp/pcr/$n.json" --json > /dev/null
  then echo "ok $n"; else echo "FAILED $n"; fi
done
```

The small `render` only computes the auto values; skip it when the stack is fixed and pass one shared
stack file to every `save`.

Each save reports `action`: `saved`, `unchanged` (the stack equals the saved one, or it is empty and
the photo was never saved) or `reverted` (an empty stack on a saved photo).

Crop to an aspect ratio, for example the largest centred 16:9 crop of the original:

```bash
pcr info "${b:-$f}" --json | jq -r '(16 / 9) as $r
  | if .width / .height > $r then (.height * $r | floor) as $w | "\((.width - $w) / 2 | floor),0,\($w),\(.height)"
    else (.width / $r | floor) as $h | "0,\((.height - $h) / 2 | floor),\(.width),\($h)" end'
```

Pass the result as `--crop x,y,w,h`, or build a `crop` op from it. Prefer whole pixels.

Undo: `pcr revert FILE --json` restores the original and drops all edits. To undo only part, save a
stack without that op. To find every edited photo in a folder, run `pcr edits` on each `list` entry and
look at `saved` (`null` means never saved) and `dirty`.

Export a copy without touching the photo: `pcr export FILE -o out.jpg --quality 92 --json`. It uses
the photo's own edits, or `--edits` / `--no-edits`, at full resolution. The output must end in `.png`,
`.jpg` or `.jpeg`.

Open the app on a folder for the user: `pcr app DIR`. It blocks until the window closes, so only run it
when the user asks to see the photos.

## Error kinds

`kind` in the JSON error, with its exit code:

| kind | exit | meaning |
| --- | --- | --- |
| `usage` | 1 | bad arguments |
| `io` | 2 | file missing or unreadable, write failed |
| `encode` | 2 | writing the image failed |
| `unsupported_output` | 2 | `-o` is not `.png`, `.jpg` or `.jpeg` |
| `read_only` | 2 | the photo's folder can't be written; save is impossible |
| `name_taken` | 2 | save would convert to a name that already exists |
| `unsupported` | 3 | not a supported image |
| `decode` | 3 | corrupt image |
| `edits` | 3 | invalid edit stack JSON (the message says what's wrong) |
| `empty_crop` | 3 | the crop is outside the image |
| `animated` | 3 | animated images can't be saved |
| `high_bit_depth` | 3 | 16-bit images can't be saved |

`list --probe` reports errors per entry (`"error": {...}` in place of the probe fields) and still exits
0. A `stale_edits` warning on stderr is not a failure.
